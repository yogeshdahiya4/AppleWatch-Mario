# PixelHop deployment guide

This document covers deploying both halves of the project.

---

## Backend (Bun + Hono on Coolify)

### One-time provisioning

```bash
# 1. Save your Coolify token (one-time):
echo "$COOLIFY_TOKEN" > ~/.coolify-token
chmod 600 ~/.coolify-token

# 2. Bootstrap project + db + app:
./tools/coolify-bootstrap.sh
```

The bootstrap is **idempotent** — re-runs are safe; it skips resources that
already exist (recorded in `.coolify-uuids.json`, gitignored).

The script creates:
1. A Coolify *project* called `applewatch-mario`
2. A *Postgres 16* database resource called `pixelhop-db` (private network only)
3. An *application* called `pixelhop-api`, sourced from `yogeshdahiya4/AppleWatch-Mario`
4. Runtime env vars: `DATABASE_URL`, `HMAC_SERVER_SECRET` (random 32 bytes), `PORT`, `NODE_ENV=production`

The HMAC server secret is generated by the script and stashed in
`.coolify-secrets.json` (gitignored, chmod 600).

### Every deploy after a code change

```bash
git push origin main           # delivers code to GitHub
./tools/coolify-deploy.sh      # CRITICAL — pushes do NOT auto-deploy on this VPS
```

`coolify-deploy.sh` reads the app uuid from `.coolify-uuids.json`, calls
`POST /api/v1/deploy?uuid=...&force=true`, and polls until the deployment
status is `finished` or `failed`. Without it, your push sits idle on GitHub
and the running container keeps serving the old image.

### Verifying

```bash
# Health check (production)
curl -k https://applewatch-mario-api.72.62.0.34.sslip.io/v1/health
# {"ok":true,"version":"…","db_ms":1,"db":true}

# Full E2E suite against production
API=https://applewatch-mario-api.72.62.0.34.sslip.io ./tools/test-api.sh
```

### Migrations

Schema migrations are written to `services/api/src/db/migrations/` by Drizzle:

```bash
cd services/api
# After editing src/db/schema.ts:
bunx drizzle-kit generate    # writes a new SQL file
git add src/db/migrations
```

The Dockerfile entrypoint runs `bunx drizzle-kit migrate` on every boot,
so every deploy picks up new migrations automatically.

### Things that will break a deploy (and why)

| Symptom | Cause | Fix |
|---|---|---|
| Build fails on `services/api/services` not found | `dockerfile_location` set as repo-absolute path | use `/Dockerfile` (relative to `base_directory`) |
| Container exits unhealthy | DATABASE_URL points to a not-yet-running db | start db: `POST /api/v1/databases/<uuid>/start` |
| Build skips devDependencies | `NODE_ENV=production` set as Coolify build-time env | only set it inside the runner stage of the Dockerfile |
| `Module not found` for `citext` | Migration 0000 lacks `CREATE EXTENSION` | first migration manually adds `CREATE EXTENSION IF NOT EXISTS citext;` |

### SSL note

The sslip.io domain uses a Let's Encrypt cert provisioned via HTTP-01.
Issuance takes 30–90 seconds after first deploy. Until then, Traefik
serves its self-signed default cert and `curl` reports cert errors —
use `-k` for testing. The cert auto-renews thereafter.

## Watch app (free-signing, sideload)

You need:
- Mac with Xcode 16+ (this repo was developed against Xcode 26.4.1)
- Apple ID (free; no $99 developer program required)
- An Apple Watch in pairing mode

### Generate the Xcode project

```bash
cd apps/watch
xcodegen generate
open PixelHop.xcodeproj
```

Use **`xcodegen generate`** instead of editing `.xcodeproj` directly —
it's deterministic from `project.yml` and avoids the dreaded
"merge conflicts in pbxproj" situation.

### One-time Xcode setup

1. **Sign in with your Apple ID:** Xcode → Settings → Accounts → "+"
2. **Install the watchOS platform components:**
   - Xcode → Settings → Components → install **watchOS 26.4** runtime
   - This is required to run on simulator OR device. ~2GB download.
   - From CLI: `xcodebuild -downloadPlatform watchOS` (requires interactive Apple ID login)
3. **Set the signing team:**
   - Open `PixelHop.xcodeproj` → click the **PixelHop Watch App** target
   - Signing & Capabilities → check **Automatically manage signing** →
     Team = "(Your Name) (Personal Team)"
   - Bundle ID stays `com.yogeshdahiya.pixelhop.watchkitapp` or pick your own

### Run on simulator

1. Pick a "Apple Watch Series 10" simulator from the run-destination dropdown
2. ⌘R to build and run

### Run on physical watch

1. Pair the watch with the Mac:
   - Mac & watch on the same Wi-Fi
   - Xcode → Window → Devices and Simulators → Watch tab
   - Click "+" or wait for the watch to appear
2. Pick the paired watch from the run-destination dropdown
3. ⌘R to build and install
4. **First run:** the watch shows "Untrusted Developer". On the watch:
   Settings → General → Device Management → trust your dev cert
5. Re-run from Xcode

⚠ **Free-signing certificates expire after 7 days.** When the app stops
launching, redo `⌘R` from Xcode to reinstall. If you want a longer
lifetime + App Store distribution, enroll in the Apple Developer
Program ($99/yr).

### Updating the build for the latest backend

If you change the backend URL, edit `APIClient.swift`:

```swift
init(baseURL: URL = URL(string: "https://applewatch-mario-api.72.62.0.34.sslip.io")!, …)
```

No regen needed for code changes; just rebuild.

## Rolling back

Backend rollback to a previous commit:

```bash
# 1. Reset to a prior commit
git reset --hard <sha>
git push -f origin main

# 2. Trigger redeploy
./tools/coolify-deploy.sh
```

Watch app: just check out an older commit and rebuild from Xcode.
